AI-Powered Job Application Portal — Project Blueprint

A resume–JD matching platform with automated candidate outreach, built for a 3rd-year full-stack project with an industry-aligned, microservices-based stack.

⚙️1. Final Tech Stack

Layer Choice Why
Frontend Next.js (App Router) Already known; industry standard; UI only — no backend logic lives here
Core backend (CRUD, auth, jobs, applications) Nest.js A real, separate backend service — cleaner ownership split across the 4-person team, stronger resume signal than folding logic into the frontend
ORM Drizzle Lighter and more SQL-first than Prisma; equally credible on a resume
Database PostgreSQL on Neon (or Supabase) Serverless Postgres, native Vercel integration, supports pgvector
Auth Clerk or Auth.js Far less setup than a custom Auth0/RBAC build; frontend handles sign-in/sign-up, Core API verifies the session token
ML matching service Python + FastAPI Separate service since the ML ecosystem is Python-based
Embedding model sentence-transformers (all-MiniLM-L6-v2) Pretrained, free, CPU-friendly, no training required
Vector storage pgvector extension on the same Postgres DB Avoids adding a separate vector database
Skill extraction spaCy NER / curated skills list Adds an explainable "missing skills" layer on top of raw similarity
Automation n8n (self-hosted or n8n cloud free tier) Orchestrates the notify-candidate workflow
Messaging WhatsApp Cloud API (Meta, official) Free tier, no third-party reseller needed
Job aggregation Adzuna API / Jooble API Legitimate, ToS-compliant alternatives to scraping LinkedIn
CI/CD GitHub Actions Lint/test gate before deploy (Vercel/Render auto-deploy on push regardless)
Deployment Vercel (Next.js frontend) + Render or Railway (Nest.js Core API, FastAPI ML service) Each backend service deploys independently
Repo structure Single monorepo (Intermatch/) with frontend, core-api, ml-service, automation as subfolders One shared git history, one place to fork/PR from, while still deploying each service independently via root-directory settings on Vercel/Render

🔄2. End-to-End Workflow (User Experience)

👔 Recruiter Side

  1. Recruiter signs up / logs in (Clerk/Auth.js, via the frontend)
  2. Recruiter posts a job: title, description, required skills, category — sent to Core API
  3. Job is stored in Postgres (via Drizzle) and becomes visible to matching candidates

👤 Candidate Side

  1. Candidate signs up and uploads a resume (PDF/DOCX) — handled by Core API
  2. Candidate selects job categories they're interested in
  3. Resume text is extracted (pdfplumber / python-docx) inside the ML service and stored

🧠 Matching Engine (Background Process)

  1. For each relevant job in the candidate's chosen category, Core API calls the FastAPI ML service, which:
    • Embeds the resume text and the JD text
    • Computes cosine similarity (semantic match)
    • Extracts skills from both texts and computes skill-overlap %
    • Combines both into a final weighted match score
  2. Score is returned to Core API and written back to Postgres against that candidate–job pair

📲 Notification Flow

  1. Core API triggers an n8n webhook when a new match score lands
  2. Score ≥ 80% → WhatsApp message via Cloud API with a direct apply link
  3. Score 50–80% → WhatsApp message noting the gap, listing missing skills, encouraging upskilling, with a note they may still get shortlisted if they apply
  4. Score < 50% → no notification (or optional low-priority digest)

🌐 Job Aggregation (Supplementary)

  1. n8n's own scheduler (cron node) pulls listings from Adzuna/Jooble periodically
  2. New listings are normalized and posted into Core API, which inserts them into the same jobs table, tagged by source
  3. These flow through the same matching pipeline as recruiter-posted jobs

📅5. Suggested Build Order (~1 month learning + build)

WEEK 01
Frontend (Next.js) scaffold + Core API (Nest.js) scaffold, Drizzle + Neon schema, Clerk/Auth.js integration on both sides — core CRUD (jobs, users, applications)
WEEK 02
FastAPI ML service + sentence-transformers + pgvector — matching endpoint, wired to Core API
WEEK 03
n8n + WhatsApp Cloud API — notification workflow, triggered from Core API
WEEK 04
End-to-end wiring, job aggregation pipeline, deployment (Vercel + Render), buffer for bugs

🚫6. Explicitly Out of Scope (Note for Report)

  • ℹ️
    No model training or fine-tuning — pretrained embeddings only
  • ℹ️
    No LLM-based scoring — kept deliberately explainable for grading/demo purposes
  • ℹ️
    LinkedIn is not used as a scraping source (ToS violation) — Adzuna/Jooble used instead
